BUILDING WITH AI: THE DEV PIPELINE

LATENCY    
CONSTRAINTS 

Runtime AI calls must  resolve within strict frame time budgets. High-latency  model responses can  break immersion and  degrade the player  

experience in real time.   
TOKEN COST  MANAGEMENT 

Every player interaction  that invokes an LLM incurs  ongoing API costs.  

Commercial viability  demands tight token  budgeting and caching  strategies at scale. 

NARRATIVE EMERGENCE 

Despite the challenges, in-game runtime AI unlocks  unprecedented narrative emergence \- enabling NPCs to  reason, respond, and evolve beyond pre-authored dialogue  trees. 

EMBEDDING AI: IN-GAME RUNTIME  
FROM SCRIPTS   
TO AGENTS

RIGID STATE-DEPENDENT BEHAVIOR 

Build scripts rely on pre-programmed rules \- if file   
changes, trigger lint; if lint fails, halt. There is no    
emergent reasoning, only if/then logic. Anything outside    
the programmed states fails silently. 

HARD-CODED LIMITATIONS 

Scripted pipelines cannot adapt to unforeseen edge    
cases or evolving project structures without costly   
manual rewrites. Every new scenario requires an engineer    
to explicitly program a new branch. 

SCALABILITY CEILING 

As projects grow more complex, the combinatorial    
explosion of pipeline states makes classic procedural    
automation unmanageable and prohibitively expensive to    
maintain. 

THE LIMITS OF SCRIPTED LOGIC  
FINITE STATE MACHINES 

"The light switch" \- explicit states, explicit transitions.  Dev example: a build script that triggers on file change.  Limit: can't handle situations you didn't pre-program. 

BEHAVIOR TREES 

"The flowchart" \- hierarchical, composable, priority ordered. Dev example: a test runner that retries on failure, branches on condition. Limit: complex pipelines  need hundreds of nodes \- gets unwieldy. 

THE AUTONOMOUS EVOLUTION \-  PART 1

UTILITY AI 

"The score calculator" \- rates all possible actions, picks    
highest. Dev example: a task scheduler that scores work    
by priority and deadline. Limit: scoring functions are    
hand-tuned, can't generalize to new inputs. 

LLM AGENTS 

"The reasoner" \- language model as the decision    
engine. Dev example: a content generator that reads   
your GDD and reasons about it. Strength: generalizes to    
situations never explicitly programmed.

PART 2  
ESTABLISHING   
THE AI CONTRACT

CREATIVE EMERGENCE 

Generative AI enables content, behavior, and narrative    
that no human explicitly authored \- expanding what    
games can be and how they respond to players. 

PREDICTABLE OUTPUTS 

Players and developers must trust that the AI system    
will not break core game mechanics, violate lore, or   
introduce logic gaps that compromise the experience. 

THE CONTRACT 

The AI contract is the explicit design commitment that    
defines where the system is free to generate and    
where it must reliably adhere to defined rules and    
constraints.

AGENT   
ARCHITECTURES FOR DEV PIPELINES

SENSE 

The agent reads environmental game data \- file states, asset manifests,    
test logs \- providing the contextual input needed for informed reasoning. 

THINK 

The agent queries a Large Language Model to reason over its inputs, plan    
multi-step actions, and determine the optimal response to the current    
game state. 

ACT 

The agent executes a targeted script or tool call \- modifying game files,    
writing code, triggering pipelines \- to produce a measurable change in the    
game environment. 

THE SENSE-THINK-ACT PARADIGM 

**QUICK CHECK** \- answer in chat: 

"A linter that reads your code files and flags broken JSON schemas \- is this a    
REACTIVE agent or a DELIBERATIVE agent?" 

(We'll discuss in 30 seconds) 

Answer: Reactive \- it responds directly to a stimulus (file change) without    
planning ahead.  
REACTIVE AGENTS 

Trigger-response mechanisms with minimal latency and low token cost. Ideal for high frequency, low-complexity tasks where speed outweighs depth of reasoning.   
DELIBERATIVE AGENTS 

Multi-step planning trees with deep reasoning chains. Best suited for complex content generation tasks where the quality of output justifies the additional API cost and latency.   
CHOOSING   
CORRECTLY 

Selecting the wrong cognitive depth wastes budget and introduces latency. Match the architecture to the task's complexity requirements and production constraints.

HOW TO GET UNSTUCK WITH AI You will get stuck in this course. That's normal. Before you post in Discord, try this: 

**DESCRIBE THE PROBLEM** 

"My agent outputs JSON but my game won't load it" \- not "it doesn't work" 

**HAVE IT READ THE DOCS** 

"Read the Phaser documentation for loading JSON files and tell me what I'm doing wrong in this code: \[paste your code\]" 

**IF YOU'RE STILL STUCK**   
**PASTE THE ERROR** 

Copy the actual error message into your LLM. "What does this error mean and how do I fix it?" 

**VERIFY THE ANSWER** 

The LLM might be wrong. Ask it: "Are you sure? Show me where in the docs this is documented." 

Post in Discord with: what you tried, the error message, what the LLM suggested, and why it didn't work. That gives your classmates enough context to help. 

**This is your troubleshooting process for the entire course. Learn it now.**
