# TICKET — BP18: The asset batch — everything UE has no C++ path for

> STATUS: open — cut 1 Aug 2026 by the founder. **Division of labour ruling in practice: the
> terminal Claude session writes CODE; the MCP-connected session writes ASSETS.** This ticket is
> the whole asset side of the board, gathered into one place so an editor session can run it as a
> batch instead of paying an editor restart per ticket (`WORK-ROUTING.md` §1).

The board's binary work is currently scattered across BP01, BP07, BP08, BP10, BP13 and the R26
rename. Each names an asset in passing; none of them is an asset ticket. An MCP session opening
the editor has to reconstruct the list from six Logs. **This is that list.**

**The law this ticket does NOT repeal — read it before the first asset.** Law 7: blockouts, table
reimports and input assets are *generated by committed scripts, never hand-placed*. **An MCP
driving the editor interactively is still hand-placing, just with a different hand** (BP16's
words). `.uasset` and `.umap` are binary and the critic cannot diff them, so **the committed,
reviewable artifact must be a script or a receipt — never the asset alone.**

BP16 step 2's proposal is **(a) MCP-as-executor**: the plan stays a committed script; the MCP
replaces the `unreal`-importing half. **That proposal has no R-number yet** (`DECISIONS-OWED.md`
D-series). Until the founder rules it, this ticket operates under (a) as the *conservative*
reading, and every step below says what it commits besides the asset.

## Steps — ordered, and the order is load-bearing

1. **The R26 rename FIRST** *(5 assets + one ini line)*. `GM_BR`/`GS_BR`/`PC_BR`/`PS_BR`/
   `BP_BRcharacter` → `BP_<CppClassWithoutPrefix>`. **First because every asset created after it
   is created under the correct names, and every asset created before it is one more referencer
   to fix up.** `git mv` is NOT an alternative — a `.uasset` stores its package name inside the
   file, so only `EditorAssetLibrary.rename_asset` rewrites the package and fixes referencers.
   `Tools/rename_r26/rename-r26.ps1` already does this headlessly and has **never been run**;
   `-PlanOnly` prints the five renames and the ini edit with no editor.
   Repoints `Config/DefaultEngine.ini`'s `GlobalDefaultGameMode`
   (`GM_BR.GM_BR_C` → `BP_BRGameMode.BP_BRGameMode_C`) **only after all five succeed**, so the
   repo is never in a state where the ini names a missing asset.
   *Commits besides the asset:* the run report + `git lfs unlock` the five paths, then re-run the
   R26 audit. Owner: **builder**.
2. **Input assets** *(8 `IA_*`, `DA_InputConfig`, 10 `IMC_Default` mappings)*. **This is the
   highest-value asset on the board: until it exists `BRPlayerController` binds nothing and
   YOU CANNOT MOVE IN PIE.** Verified absent against the live editor on 1 Aug —
   `/Game/Input/DA_InputConfig` does not exist and only 4 of the needed `IA_*` are present.
   `Tools/gen_input/build-input.ps1` exists and has never been run (`-PlanOnly` first).
   *Acceptance:* the config passes `UBRInputConfig::IsDataValid`. Owner: **builder**.
3. **Import the seven CSVs to DataTable/CurveTable assets** (BP13 step 6). Verified against the
   live editor: `/Game/Data` holds **zero assets** — the folder exists, the CSVs are loose files,
   **no DataTable or CurveTable has ever been imported, so no tuning number is read at runtime.**
   `Tools/reimport-tables.ps1` is written but **its commandlet invocation has never completed
   successfully here** — budget debugging time and do not schedule it before steps 1–2, which are
   known-good scripts.
   **Run `Tools/validate_data_tags/validate_data_tags.py` BEFORE importing.** It resolves
   tag-valued CSV columns against the native tag registry and exits nonzero on a dangle; a
   reimport is exactly when a dangling tag becomes a runtime problem. It currently passes.
   Owner: **builder**.
4. **Arena blockout `.umap`** (BP07). Manifest v3 lands and validates PASS; the `.umap` has never
   been built. `Tools/blockout/` is the harder generator (38 actors, World Partition uncertainty)
   — it is deliberately **not** the first thing this ticket runs. Owner: **builder**.
5. **`ST_Bot` StateTree + EQS queries** (BP08). The C++ brain, `BRBotBrain`, `BRBotFacts`,
   `DT_BotTuning` and `DT_BotAmbitions` all landed; the StateTree asset is the Tier-4 gap.
   Owner: **ai-builder**.
6. **WBP widget layouts** (BP10). The C++ layer and ViewModels landed; **no WBP assets exist.**
   Tier 4 covers *layout and anchors only* — state and binding live in the C++ parent and the
   ViewModel, and a WBP carrying anything else is a `high` finding
   (`data-and-assets.md`). Owner: **ui-builder**.
