# TICKET — BP16: The UE 5.8 editor MCP — a live hand inside a running editor

> STATUS: open — cut 1 Aug 2026 by the founder. **Terminal-only, and stranger than the other
> terminal tickets: it needs a *running Unreal editor*, not merely an installed one.** Nothing
> in this ticket can be done headless, in CI, or on a machine without the project open.

Founder directive: the UE 5.8 MCP is hosted **inside the editor itself** — start Unreal, and the
editor exposes an MCP server an agent can drive live. That replaces the slowest, most awkward
half of our asset pipeline: the `UnrealEditor-Cmd -run=pythonscript` executor scripts we write
blind, run once, and debug through a log file.

**The law it does NOT repeal:** law 7 says blockouts, table reimports, and input assets are
*generated by committed scripts, never hand-placed*. **An MCP driving the editor interactively is
still hand-placing — just with a different hand.** The reviewable artifact must remain a
committed script, because `.uasset` and `.umap` are binary and the critic cannot diff them. This
ticket's real work is defining where the MCP sits relative to that law, not wiring a transport.

**Ordering law:** step 1 gates everything (nothing is knowable until the surface is enumerated
against a live editor). Steps 2–3 in order. Step 4 needs steps 1–3. Step 5 closes.

## Kickoff (machine-checkable — the tickets skill verifies these BEFORE a claim)

- requires: editor-live  — the MCP server is hosted INSIDE a running editor; an installed engine is not enough
- `Breachpoint.uproject` exists and `BreachpointEditor` **currently builds** — verified by

- A UE 5.8 editor instance can be launched on this project and **stays open** (it is the MCP

- The MCP server is reachable from the session — its tools resolve by name, not merely
  "installed". **A tool that does not appear in the session's tool list does not exist**, and
  this session verified exactly that on 1 Aug 2026 (see Log)
- owner_path: `Tools/ue_mcp/`, `docs/contracts/` (the fill-in in step 3 only)

## Steps (in order)

0. **Desk research — DONE (1 Aug 2026, `Tools/ue_mcp/RESEARCH.md`).** Setup path, endpoint
   (`http://127.0.0.1:8000/mcp`), the `ModelContextProtocol.GenerateClientConfig ClaudeCode`
   console command, documented tool categories, and Epic's experimental caveats. Verdict:
   a cloud container **cannot** host this (loopback + Epic's "not designed for remote use";
   tunnelling considered and rejected as exposing an unauthenticated mutation endpoint to buy
   a capability the local session already has). It also **corrects the framing this ticket was
   cut under: the MCP is not an agent** — it is the same Claude Code session with the editor
   open, so no prompt-handoff ticket format is needed. **This does not close step 1:**
   documentation is not the surface, and where they disagree the editor is right.

1. **Enumerate the real surface, against a live editor** — not against documentation.
   Start the editor, connect, and produce `Tools/ue_mcp/SURFACE.md`: every tool the MCP exposes,
   its arguments, what it returns, and **what it refuses**. For each, one line on whether it is
   read-only (query an asset, screenshot a viewport) or mutating (create an asset, place an
   actor, save a level). Owner: **builder**.
   > This is step 1 because every other step's cost is unknown until it exists. Our two existing
   > generators (`Tools/blockout/`, `Tools/gen_input/`) were each written to a **guessed** editor
   > API; this is the first chance to check what the editor actually offers.

2. **Decide the law-7 boundary and record it as a ruling.** The question, stated plainly: *when
   an agent creates an asset through the MCP, what is the committed, reviewable artifact?*
   Three candidate answers, and the packet must pick one with a reason:
   - **(a) MCP is an executor only.** The plan stays a committed script; the MCP replaces the
     `unreal`-importing half. Reviewable artifact unchanged. Cheapest, most conservative.
   - **(b) MCP calls are recorded to a committed transcript** which can be replayed. Reviewable
     artifact is the transcript; determinism must be proven by replay.
   - **(c) MCP is exploratory only** — permitted for reading, screenshots and one-off inspection,
     never for landing an asset that ships.
   Owner: **lead** decides, **critic** refutes. The answer goes in `docs/DESIGN-RULINGS.md`.

3. **Fill in `docs/contracts/data-and-assets.md`** with the outcome of step 2, so the rule lives
   in the contract a builder actually reads, not only in the rulings ledger. Owner: **lead**.

4. **Retrofit ONE existing generator and measure it.** `Tools/gen_input/` is the candidate — it
   is small, its output is verifiable (`UBRInputConfig::IsDataValid`), and it is currently
   blocked on nothing but an editor being free. Port its executor half to the MCP path, run it,
   and record: wall-clock vs. the `UnrealEditor-Cmd` path, lines of code deleted, and **any
   behaviour the MCP could not reproduce**. Owner: **builder**.
   > One, not both. `Tools/blockout/` is the harder case (38 actors, a `.umap`, World Partition
   > uncertainty) and should not be the experiment.

5. **Adversarial pass (critic, REFUTER).** Each answer needs input → wrong outcome, not vibes:
   - Can an agent land a `.uasset` through the MCP that no committed script can reproduce?
   - Can an MCP mutation bypass `guard_laws.py` entirely? (**It can** — the hook is a PreToolUse
     guard on `Edit`/`Write` `file_path`; an MCP tool call is neither. State the consequence.)
   - Can two agents drive one editor at once, and what happens if they do?
   - Does an MCP-created asset differ from the script-created one in any way a diff would miss?
   Owner: **critic**.

**1 Aug 2026 — cut, with the reason for cutting it recorded.**

The founder asked whether the crew was wasting effort writing editor-driver scripts that the UE
MCP already covers. **Checked rather than assumed:** the session's MCP servers are Atlassian,
Canva, Figma, Gmail, Google Calendar, Google Drive, Mobbin, Notion, Supabase, Supermetrics,
Vercel and higgsfield. **No Unreal server is connected to this session.** The `ue-editor` skill
and the `arena-architect` definition both say *"drives the UE editor via MCP **when available**"* —
conditional, and it was not.

So the two generators written today (`Tools/blockout/`, `Tools/gen_input/`) were not waste: they
were the only available path, and law 7 requires the script to exist regardless of who runs it.
What an MCP would have saved is the **executor half** of each — roughly a third of the work —
not the planning half that carries every reviewable decision.

*Why this is its own ticket rather than a line in BP07 or BP01:* the interesting question is not
transport, it is **jurisdiction**. `guard_laws.py` enforces law 5 on `Edit`/`Write` tool calls by
`file_path`. An MCP tool call has neither, so **every mechanical protection this project built
tonight is blind to it.** That is not a reason to refuse the MCP — it is a reason to decide the
boundary deliberately, in a ticket, before an agent lands its first `.uasset` through it.
